## 1. 判断与证据范围

目前需要一次有边界的结构收敛。上一轮删除了旧执行入口和死代码，但没有解决执行规则漂移、查询范围过大、持久化模型与界面视图混用、代码可读性等债务。这些批评有依据。现有分层、能力隔离和恢复机制解决的是实际问题，继续保留。

第一份报告总体更接近代码事实，也明确区分了性能风险与已验证行为。第二份报告提供了更多线索，但部分事实和结论需要修正；“工业级”“彻底杜绝”和百分制评分没有足够测量依据，不用于确定优先级。165 项测试通过说明已有场景通过，不证明故障、权限和规模边界已经穷尽。

本次读取了两份报告涉及的执行、存储、工作区、Git、工具、角色、配置、启动与界面实现。四个隔离临时探针通过，复核了：

1. 实际对话校验异常被 `publicError()` 转为 STORAGE，丢失重新选择对话的提示。
2. 单独执行子控制器，其截止计时器取消引擎后，终态为 cancelled，未保存截止原因。此探针没有覆盖完整任务组中根/子计时器的全部竞态。
3. ESLint 允许 core 导入 application；现有边界测试没有覆盖该情况。
4. 一个项目快照读取了另一个项目的 30 条操作正文；同一资料文件在该次快照中至少读三次，随后文件保存也调用整个 operations bucket 的读取。

没有进行真机压力测试，没有复现 OOM，也没有测量界面渲染耗时。此处将风险、静态事实和行为验证分别记录。

| 全部空 catch 应删除                     | 不采纳机械整改。队列尾部容错、观察者隔离、关闭网络读取和已由收尾 await 检查的后台写链具有用途；真正缺失反馈的业务失败需要补错误状态和脱敏诊断             |
| 全部非空断言应删除                      | 优先检查存储记录、配置租约和异步生命周期边界；由已验证不变量支撑的断言可保留并说明。数量不等于缺陷数量                                                    |
| 单行多语句影响维护                      | 采纳。并发、恢复和错误处理优先展开；排版改动单独提交，不与状态机/存储迁移混在一起，不以清零某个统计数作为验收                                             |

| state/ref 双镜像就是两个事实来源        | 当前 setEditor 已封装同步更新，ref 用于读取最新异步状态，不是天然错误。但调用者仍有手动 ref 写入，需要禁止外部双写并验证异步保存/切换的竞态               |
| 初始化必须改成通用 RecoveryOrchestrator | 暂缓。显式顺序本身合理；优先命名启动阶段、写清依赖、失败即阻断启动并测试时序，不引入通用 DAG/插件管道                                                     |

复核额外发现：浏览器 `MetadataStore.all(bucket)` 使用整个 records store 的 getAll/getAllKeys，再过滤 bucket；不只 operations 查询，其他 bucket 查询也可能复制大量无关记录。首先应修为 bucket 范围读取，并为业务热查询提供专门端口。

## 4. 必须继续成立的不变量

- UI 使用运行时裁剪的 AppServices；core/application 保持平台无关，Pi 与原生库留在 adapters。
- 同项目文件、index、HEAD 修改共用串行队列；不同项目保持并行。统一队列代码不代表统一成全局队列。
- Git 是文件历史来源，SQLite 是业务元数据来源；跨存储依然依赖日志和回执，不能用一笔 SQLite 事务替代文件/Git 恢复。
- reader/reviewer 只接收精确授权的固定快照；writer 只接收候选能力；根任务预检后合入。共享代码不能扩大注入的能力。
- 工具意图在副作用前持久化；终态及必要回执保存后才能发布完成；未知 MCP 副作用不能盲目重放。
- 请求槽在模型返回后、等待子任务前释放；用户取消、排队取消、应用中断和预算停止有明确不同语义。
- 当前格式的运行/文件/凭证中断恢复可重试，不能与旧格式兼容一起删除；旧版本数据没有升级/降级兼容承诺。

## 5. 实施顺序与可验收交付

### 第 1 批：行为正确性与边界约束

先做可独立评审的修复，不同时替换引擎或存储格式。

- 明确 `TerminationReason`：用户取消、祖先取消、截止时间、子配额/组预算耗尽、引擎错误、存储故障。原因通过控制对象传播并记录，不能由 error 文案或 aborted 倒推。单个运行采用首次明确接受的停止原因，祖先停止传递真实来源；派发与终止前复核截止时间，避免计时器延迟误判完成。预算耗尽与用户停止不能相互覆盖，存储回执失败不能伪装为已持久化终态。
- 根/子共用终态判定函数，保留各自收尾。覆盖子计时器先触发、根计时器先触发、用户停止与超时接近、子配额不足而根仍可汇总等场景。
- 业务错误从产生处使用 AppError；取消、冲突、权限/校验、限额与存储故障分类稳定。保留未知异常脱敏，不再匹配中文前缀。相关错误源/调用者/回归与正则删除在同一交付中完成，不留下两种错误契约。
- `defineTool` 必须声明 effect；角色 allowedEffects/mayDelegate 参与实际构建和派发。先覆盖内置角色，不增加自定义角色功能。
- 单独约束 core 禁止 application，补 alias、相对导入和 type import 的禁止/允许用例。继续允许平台无关的 schema 类型。

验收：新增回归在修复前能复现缺陷，修复后正确；既有取消、请求槽释放、MCP unknown、writer 合入与恢复验证保持通过。

### 第 2 批：关闭无界日志读取，建立测量基线

通过有业务语义的 `OperationJournal` 查询/写入端口处理日志；不把全局 MetadataStore 扩展成允许任意 SQL 的接口。

- 将操作摘要与恢复正文的读取分开；按 projectId/runId/phase 查询，恢复只加载待完成项正文，界面只加载摘要。nextSequence、workspace.snapshot、taskFinal、undo 等调用者一起迁移，禁止修好序号后继续从其他路径全读正文。
- 项目序号单独维护，递增与 prepared 日志在同一元数据批次中保存，并受同一项目队列协调。允许序号有空隙，禁止回退、复用或把 get+put 当成天然原子增量。
- 当前格式初始化序号与索引，旧格式开发数据可重建，不迁移旧日志；Skills 的 scoped store 支持同样的原子批次。
- 浏览器使用 bucket 范围和业务索引读取；SQLite 针对热查询建立实际可利用的列/索引或摘要表。底层可以继续保留 KV 承载低频配置，避免同时重写所有存储。
- 记录冷启动、文件保存、刷新、序列化字节、查询条数、文件读取次数与内存峰值。使用隔离数据集覆盖大量操作、小文件集合、长轨迹和大图片；原生设备结果与浏览器结果分别记录。

验收：其他项目或已完成操作的正文数量增长，不增加一次本项目序号分配/摘要刷新的正文读取量；崩溃后序号仍单调、重复操作仍幂等。暂不声称已经解决所有大项目性能问题。

### 第 3 批：当前数据模型与有界界面查询

- 分离当前 RunRecord、LaunchSnapshot、RunSummary、RunDetail 和 Trace；RunRecord 不再继承兼容展示 DTO。排队任务没有基线等必要可空状态用明确状态类型表达，不能简单要求所有字段非空。
- 当前运行仅以 trace 表达过程；删除 events、Legacy DTO、历史只读转换和迁移记录，不增加 ImportedHistoryRecord。
- 对话图按当前格式初始化；“任务已入队但草稿回执尚未完成”的日常恢复保留，删除旧任务补 conversationId 等格式迁移。
- 工作台按当前对话加载最近一页摘要；打开运行详情时加载轨迹，展开子任务时加载该子任务。启动不再 runs.views 全量 hydrate 所有项目的历史，改查对话归属和待修复草稿所需的轻量信息。
- Git 历史提供基于 OID 的游标和继续加载；恢复 findOperation 保留可靠的逐页搜索/提交证据。索引未落盘的 Git 成功窗口必须继续可恢复。

验收：单页调用只加载规定数量的摘要，不读取所有历史 trace/transcript；切换项目/对话不串数据，分页新增不漏重；当前格式初始化、格式不匹配、草稿回执失败和 Git 成功但数据库回执丢失均有验证。

### 第 4 批：公共机制收敛与持续写入成本

- 提取小型执行驱动，统一请求/工具准入、终止原因、取消订阅和资源释放。根控制器负责委派汇总，子控制器负责受限上下文和候选收束；不建设角色插件框架。
- 定义最小文件读取能力，复用 schema、分页、搜索和图片返回规则。后端绑定固定项目/快照/授权路径，授权检查继续在后端执行；写入仍由独立能力承担。
- 技能包版本保存作为显式用例，使用共同文件日志和明确的提交操作；考虑文件应用后、Git 提交后、回执保存前的恢复。不能以“把自动提交改为稍后调用 commit”替代完整恢复编排。
- 轨迹以稳定节点 ID 和版本更新，完整 transcript 按回合或分块追加；最后终态与必要节点/回执仍同批提交。正文可合并刷新，但副作用前的意图 flush 不得延迟。
- 对活动运行避免每个内容分片复制完整任务树并刷新整个工作台；持久化节流和 UI 通知节流分别测量。文件修订复用受控写入已知值，未知外部修改/恢复后仍有失效和重新验证机制，写前版本检查保留。

验收：相同输入下根/子公共行为一致；三种文件来源输出契约一致且隔离不变；长轨迹单次持久化只更新变化部分；终态、失败恢复、候选归属与 MCP unknown 不退化。

### 第 5 批：界面契约与维护质量

- useWorkbench 保留装配职责，输出按会话、编辑器、文件、Git、运行、弹层组织的窄接口；组件接收所需能力并使用相应订阅。拆 Hook 但继续广播同一大对象不能作为完成标准。
- editor/composer 各有唯一更新入口；调用者不再手动写 ref，异步保存完成用文档/对话身份和版本确认结果是否仍可应用。保留保存时继续输入、保存期间切换、Agent 修改与未保存编辑并存的验证。
- 稳定的 AppServices 命令/查询显式定义接口，由实现满足；保留 facade 的实际裁剪与错误边界。
- 合并小型串行队列和 JSON 快照工具，保留各队列的作用域与失败策略。按语义命名阈值，不建立收纳一切的 constants/util 文件。
- 单独进行可读性排版；并发、状态机、迁移和权限代码优先。关键非空断言改为经过验证的输入/不变量，重要后台失败有脱敏诊断和用户可理解的状态。
- 启动流程命名阶段与依赖，测试必要恢复失败时不创建可派发的内核；暂不引入通用恢复管道。

- 收敛目录粒度：移除本地空目录残留、扁平化小型单文件模块、合并 agent/agents 分组；保留真实业务、协议、平台和路由边界。具体候选路径见实施方案第 2.1 节，路径调整独立提交，不用重导出兼容文件抵消整理收益。

验收：核心规则不再靠提示文字、位置布尔参数或工具名称隐式决定；公共契约可独立类型检查；界面竞态回归保持通过。实际渲染收益由 profiler 和同设备对比确认。

## 6. 交付方式与暂缓范围

每批再拆为小提交：行为修复、契约/格式、存储实现、排版分开评审；同一交付统一更新调用者/测试/文档并删除旧路径，不为保留历史接口留下常驻桥接。所有语义改动运行 `npm run check`，相关界面做浏览器回归。日志、事务、序号、初始化和恢复变化增加 SQLite/IndexedDB 故障注入及 Android 实存验证；依赖或 Expo 配置变化运行 Expo Doctor。没有原生/真机验证的结果不写成原生已通过。

近期优先交付第 1 批与第 2 批；第 3 批确定当前 DTO 后直接改存储/界面，开发数据可重建。后续批次按测量和实际结果调整，不以兼容旧原型为由拖延清理。

暂缓：Pi 替换、完整 ORM/全库规范化、自定义角色、插件化沙箱、国际化平台、libgit2 替换和通用 RecoveryOrchestrator。Pi 的消息/流接口隔离可独立处理。开发实例格式重建允许清理该实例的业务/工作区数据；当前格式的在线 GC 是另一项功能，仍须核对 undo/proposal/Skills/恢复引用，不能让运行中日志失去证据。

本次交付仅新增本计划及 design 索引，未修改实现或两份外部报告。四项临时探针复核完成后已移除；随后 `npm run check` 通过（TypeScript、ESLint、22 个套件/165 项测试）。本轮未重跑浏览器或原生回归，没有使用付费模型。
