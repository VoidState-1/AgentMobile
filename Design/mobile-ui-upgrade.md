## 1. 设计输入与范围

用户要求先完成手机体验，全面改善导航、信息层级和操作反馈。用户明确否定首轮的大间距、大圆角、低密度卡片、说明式文案、分离的项目与对话管理、重复标题栏和专门的标题重命名按钮。

本稿以“紧凑移动工作区”为单一设计方向。用户追加四区底栏、适量主题色、克制的卡片输入框与 Codex 风格连续工具折叠后，已将主流程实装到 React Native 并连接现有 AppServices。早期对话内原型仍是合成数据，正式实现以 docs/design.md 和源码为准。

设计优先考虑元素同时表达关系、状态与操作，减少常驻区域和寻找成本。密度通过结构、复用、对齐和渐进展开提高，正文保持可读，交互热区保留约 44px。

## 2. 常驻结构

对话主界面保留一层 48px 顶栏，底部为对话、文件、Git、设置四区；键盘展开时底栏收起。正文直接排布，移除重复的软件/对话标题栏与大结果卡。

顶栏从左到右为：树形侧栏入口、可直接改名的当前对话标题、新建对话。文件、Git 与设置由底栏进入，Git 更改数附着于底栏图标。主题色用于选中项、状态、发送与局部重点，页面维持中性表面。

输入区采用卡片外形，手机横向外边距 8px、圆角 8px；内部为可扩展输入、添加入口、当前模型、草稿状态与发送/停止。引用文件出现后才占据一行。模型选择在输入附近展开为紧凑菜单，切换作用于后续任务；运行记录仍保存启动时模型。

## 3. 项目与对话树

左侧抽屉统一管理项目与对话。项目为父节点，对话通过缩进和连续树线表达归属。节点选中背景与边线表达当前位置；草稿、运行状态附着于节点。

- 点击项目行展开或收起；项目行末的加号在该项目创建对话。
- 点击对话切换，保留各自草稿和模型选择。
- 对话长按显示上下文操作；项目行保留展开和新建对话。正式实现未增加项目重命名 API。
- 对话的重命名和归档不再通过独立的列表管理窗口；短输入与确认仍使用输入弹层。
- 搜索按需替换侧栏标题区；正常浏览不额外占据一行搜索栏。
- 新建项目及归档入口放在侧栏；应用设置放在第四个底栏区域。

正式实现已接入切换、草稿、新建、改名、归档和恢复，保留按项目恢复选择、运行中归档限制、跨项目活动状态及已有业务权限。跨项目恢复归档对话时同样保护未保存编辑。

## 4. 用对象承载操作

| 对象       | 默认表达                     | 交互                                 |
| ---------- | ---------------------------- | ------------------------------------ |
| 对话标题   | 当前对话                     | 点击原位编辑，确认或离焦保存         |
| 项目节点   | 分组、展开状态、项目更改数   | 点击展开；行末加号新建；长按管理     |
| 对话节点   | 标题、选中、草稿/运行状态    | 点击切换；长按管理                   |
| 执行摘要   | 当前动作或实际完成摘要       | 点击展开工具与子任务；运行时显示停止 |
| 输出文件行 | 文件身份、修改状态、增删行数 | 文件名打开正文；增删数打开差异       |
| 文件标题   | 当前文件、未保存标记         | 点击改名；编辑时显示保存动作         |
| 更改文件行 | 新增/修改/删除、路径、增删数 | 点击查看差异；复选框选择暂存范围     |

对象的可交互区域通过位置、选中与按下反馈形成一致规则。正式实现仍需核对实际文件存在性、路径权限和版本，不凭模型文本猜测文件结果。

## 5. 对话与执行

普通回复采用直接排版，减少重复的 Agent 名称、模型标签、头像和结果说明。用户消息使用小幅背景区分，不增加大面积气泡留白。

连续工具调用按读取、搜索、图片、修改、Git、Skills、MCP、子 Agent 图标汇总，可展开查看，展开区域最高 280px 并可滚动。正文与公开思考过程/推理摘要按模型实际返回保留，不跨越这些节点合并。异常与子任务组默认展开，未知效果仍明确显示。停止入口保留在输入区与子任务上，已有文件效果仍需准确保存。

输出文件使用紧凑文件行：文件名直达当前产物，变化图标打开任务差异；底栏 Git 徽标显示当前待提交数量。省去“打开文档”“查看更改”两枚大按钮及反复解释文件已保存的文案。

正式摘要必须来自真实轨迹和文件效果；原型计数及执行是合成数据。中断、错误、未知 MCP 结果和未保存冲突仍需必要的局部文字，不以精简文案为由隐藏关键原因。

## 6. 文件、编辑与 Git

文件页直接使用单层顶栏和文件树。文件夹、缩进、文件名和修改标记表达结构；搜索按需在顶栏展开。主要文件行高约 44px。

文档阅读使用页面正文；编辑按钮进入编辑模式，顶栏切为保存动作。未保存用文件标题旁的小标记表示；返回时才询问保存、放弃或继续编辑。文件名可原位改名，其余动作在文件上下文菜单。

更改页用未暂存/已暂存分组和紧凑行表达真实 Git 状态。选中后底部操作变为暂存；有暂存内容时可提交，提交说明在操作区原位输入。提交历史由顶栏入口切换。

单文件差异采用紧凑行号、增删符号和语义色，比较范围只显示一行。保留只提交已暂存内容、暂存后再编辑、部分提交、取消暂存和任务占用限制。

## 7. 视觉节奏

- 以中性色、细分隔线、对齐和缩进组织界面，容器内部圆角以 3–5px 为主。
- 对话正文默认 14px，原型可调整到 16px；正文行距约 1.6。输入保持 16px。
- 页面边距约 9–14px，常见信息间隔 4–8px，消息分组约 12–15px。
- 标题约 15px，状态/路径约 11–12px；辅助信息不单独撑起大块区域。
- 控件视觉可以紧凑，点击区域保持约 44px；不通过重叠点击区域挤压布局。
- 深浅主题共享层级，颜色用于修改、增删和状态表达，不给普通并列条目分配装饰色。
- 日常操作省去说明书式文字。异常原因、权限边界和不可逆后果在触发位置提供必要反馈。

## 8. 原型与实施边界

本轮交互覆盖单层顶栏、树形侧栏、切换与草稿、原位标题编辑、长按菜单、执行折叠与停止、模型选择、文件引用、文件树、阅读编辑、未保存保护、差异、暂存和提交。

复杂模型/连接、Agent、MCP、Skills 配置流程沿用现有用例，通用表单已统一更紧凑的间距、圆角与输入字号。Web 回归覆盖真实应用流程和模拟协议；Android 模拟器已验证软键盘、编辑保护、强停恢复与主题。侧栏滑动未纳入首版，侧栏采用按钮打开、关闭按钮/遮罩/系统返回关闭。iOS、arm64 真机、完整屏幕阅读器与动态字号仍需独立验收。

实施阶段：

1. 已接入：统一基础样式、移动导航与项目对话树。
2. 已接入：现有会话、运行、文件与 Git 主流程，保留 AppServices 分层及恢复语义。
3. 后续打磨：复杂配置的信息层级、长列表性能、滑动交互与完整可访问性。
4. 按平台验收：当前以 Web 和 Android 模拟器为本轮证据，iOS 与真机另验。

主工作流已接入正式界面。验证以本轮实际执行的类型、分层、领域、Web 和 Android 检查为准，原型演示不作为应用验收。复杂配置详情沿用现有用例，通用表单已收紧间距和圆角；iOS、arm64 真机及完整可访问性仍需单独验证。
