# Agent Skills 实施设计

日期：2026-10-14。状态：已接入原型；验证记录见 [validation.md](validation.md)。

## 使用方式与范围

“设置 → Agent Skills”管理本地技能库，支持新建、搜索、导入 SKILL.md/ZIP、编辑说明与文字资源、查看图片资源、按项目启用、导出 ZIP、查看和恢复历史版本、删除。技能库独立于项目资料；同一项目下所有对话共享启用记录。技能内容更新后撤销旧启用，用户查看新版本后重新启用。

消息输入区的“选择技能”会插入 `$技能名`。明确调用由宿主在首个模型请求之前加载；未安装或未在当前项目启用时停止启动并保留草稿。普通 `$100` 金额不识别为技能。没有明确指定时，模型根据目录匹配任务，调用 load_skill 加载正文，再用 read_skill_resource 读取引用资料。加载记录纳入工作轨迹，不把技能正文集中在所有任务的顶部。

演示模式仍是固定流程，不进行技能语义理解；可以显示用户明确选择的加载步骤，但不能用演示结果证明模型按技能执行。真实模型模式支持三种现有协议，技能不绑定特定供应商。

## 标准格式与移动端导入

采用 [Agent Skills 标准](https://agentskills.io/specification)：根 SKILL.md 包含 YAML frontmatter 与 Markdown 正文。name 和 description 必需；license、compatibility、metadata、allowed-tools 可选。保留原始文件，支持 YAML 块标量、UTF-8 BOM 与 CRLF；使用 YAML 2.9.1 解析，不自行按冒号拆字段。名称首版限小写 ASCII 字母、数字和单连字符，长度 1–64；description 最多 1,024 字符。重复字段、错误类型、未知 YAML 标签、别名或无正文会报错。客户端私有扩展字段不会增加宿主能力。

单个 Markdown 文件作为 SKILL.md 导入；ZIP 可包含一个或多个技能目录及 references/assets/scripts 等配套文件，也可导入仓库 ZIP 内的多个技能目录。按 frontmatter.name 规范化目录；同名技能在预览中标注更新，不会静默产生两份同名目录。技能目录互相嵌套、同包同名和重复大小写路径会拒绝。

使用 fflate 0.8.3：先验证 ZIP 中央目录，再以 4 KB 压缩输入分块解压，逐块核对实际输出容量，不能仅相信 ZIP 声明大小。拒绝绝对路径、回退路径、反斜杠、设备名、数据库与凭证扩展名；隐藏文件、.git、node_modules 和 __MACOSX 不导入。ZIP 内容只作为数据写入受控文件库，不创建原生符号链接，不安装依赖或执行脚本。

资源路径相对于当前技能根目录。文本引用可分页读取；PNG/JPEG/WebP 在导入时验证，模型开启图片输入后才可返回图片。其他二进制资源保留供导出，暂不交给模型。新文字资源可在编辑页加入 references/ 或 assets/，仍需保存整个技能后生效；资源编辑与技能编辑均保护未保存内容。

## 持久化、Git 与恢复

技能正文与资源存放在宿主管理的独立 Git 工作区，逻辑目录为 skills/<name>/...。该工作区使用固定内部标识，不进入用户项目列表，也不通过 list_files/read_text 暴露。模型只获得技能名称、描述及受控相对资源路径，没有真实设备路径、.git 或数据库访问接口。

SQLite skills/configuration 保存版本化配置图和项目启用指纹；skill-library:* 保存独立工作区元数据与操作日志。Git 文件树是技能内容来源，SQLite 不作为技能正文的权威来源；操作日志保留恢复所需的 before/after，延续现有工作区恢复方案。Zustand 不保存技能内容或启用图。

包安装、更新和删除使用一次受控多文件操作：检查基础 Git HEAD → 保存操作日志 → 应用全部文件 → Git 提交 → 记录操作终态 → 从提交树重新派生目录 → 保存配置图。Git 与 SQLite 没有跨存储事务。中断后先恢复日志，再重新扫描 Git；如果 Git 已成功提交而技能配置未保存，初始化会补齐目录并撤销不匹配的项目启用。未完成的保存会阻止本进程继续使用旧图启动技能任务，提示重开恢复。

技能版本指纹由全部资源相对路径与 Git blob 修订号派生，正文或引用资源变化均会更新。历史恢复只替换选中的技能，形成新提交，保留其他技能和旧历史。历史界面最多检查最近 30 条库提交。删除后旧 Git 数据保留，首版未提供已删除技能的恢复入口或历史清理。

## Agent 集成与版本固定

任务启动通过 SkillService.capture 获取当前项目启用的技能快照。系统提示词只加入 name/description/compatibility 目录与使用规则。load_skill 的 name schema 限定到本次任务可用名称；没有可用技能时不注册技能工具。正文返回时附带资源目录和使用边界，不自动读取资源。

明确调用的正文加入本次任务系统上下文；自动加载的正文进入 Pi 工具结果上下文。单个任务中重复加载返回“已加载”，避免重复注入。下一任务重新按当前启用图匹配，不从历史任务重放旧技能正文或工具调用；当前没有自动上下文压缩，未来压缩时需保护已激活技能内容。

TaskRecord.skillsSnapshot 保存名称、说明、版本、Git commit 和资源清单；skillActivations 保存明确/Agent 选择、版本和时间。读取正文和资源使用任务快照的 Git commit，因此运行中编辑、停用或删除技能不会改变当前任务。同一对话的新任务采用当前配置。

allowed-tools 只展示为兼容信息。技能说明不能授予 shell、任意原生调用、网络访问或 MCP 权限；只能使用本次任务原本具备的本地工具与已授权远程 MCP。scripts/ 可以阅读，不执行；要求 Python、shell、浏览器自动化或文档渲染环境的外部技能不会自动获得这些环境，Agent 必须说明不可执行的步骤。

## 容量与尚未实现的能力

技能库最多 128 个技能，单项目最多启用 64 个；库内资源最多 4,096 项。一次 ZIP 最多 512 项、压缩输入和展开数据各最多 20 MB。SKILL.md 最多 64 KB，其中 YAML 元数据最多 8 KB；图片最多 4 MB，其他文件最多 1 MB；显式/自动激活正文累计最多 120,000 字符。文本资源默认按 12,000 字符读取，可配置单段至 100,000。模型上下文、输出和全局 Agent 预算仍适用。

首版未实现远程技能市场、URL/Git 自动下载、手机原生目录扫描、项目级目录覆盖规则、脚本执行、自动依赖安装、技能分叉/直接改名、已删除技能恢复、签名验证、历史清理或跨设备同步。依赖脚本与特殊运行环境的技能需要后续受控执行方案，不能直接承诺兼容所有桌面技能。
