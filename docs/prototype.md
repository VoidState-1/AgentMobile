# 原型体验与实现说明

日期：2026-10-13。

## 快速体验

运行 npm run web，打开终端显示的地址；或运行 npm run build:web 后运行 npm run preview，打开 http://127.0.0.1:4180。

1. 新建项目，例如“旅行资料”。
2. 切到“资料”，打开 notes.md，在“编辑”模式输入内容并保存；或导入文本/图片。
3. 切到“会话”，选择或新建项目下的对话，输入任务并点击发送箭头。
4. 默认演示经过 Pi 的 list_files → read_text → write_text 循环，生成 documents/summary.md。
5. 点击“查看变化”，检查新文件；“撤销修改”恢复任务开始前的文件内容。
6. 在“版本”查看各次真实 Git 提交，先预览变化，再恢复；恢复会生成新提交。
7. 关闭并重新打开页面，项目和资料仍在浏览器本地存储中。

演示模式的步骤和文本模板都是预设的；它验证执行链路，不提供语义理解。

## 项目与对话

- 手机端在对话栏点击下拉切换，“+”新建，铅笔修改名称；桌面侧栏直接列出当前项目的对话。
- 每个对话独立保存消息、输入草稿、参考文件和模型选择；新对话不会携带另一对话的聊天历史。
- 项目文件与 Git 版本共享；任务仍使用项目写锁。同一时间运行一个任务，其他对话可先准备草稿，或返回正在运行的对话。
- 草稿自动保存到本地元数据，状态变为“草稿已保存”后可刷新/重开恢复。切换项目时记住各项目最后打开的对话。
- 对话列表可搜索、归档和恢复。归档保留历史、草稿和模型选择，运行中暂不允许归档；永久删除尚未开放。
- 原有单对话项目自动迁入“原有对话”，旧消息和原模型选择保持可读。

## 配置真实模型

右上角“设置 → 模型与供应商 → 添加连接”，选择 DeepSeek、Anthropic、Gemini 或自定义模板：

1. 填写连接名称、基础地址、协议、认证和 API Key，保存连接。同供应商可保存多份连接，凭证独立。
2. “检测连接并发现模型”读取服务目录，不生成内容；目录不可用时使用“手工添加”。Gemini 可填写模型名称或 models/名称。
3. 打开模型详情，编辑显示名、收藏、能力和参数；需要图片时开启“允许图片输入”。
4. 按需执行明确标为可能计费的文本、工具、图片检测；各平台结果分别保留，未知能力和失败原因分别展示。
5. 设置全局或当前项目默认；会话输入区“模型设置”打开搜索/收藏选择器，明确选择优先于项目和全局默认。也可随时选择演示模式。

已保存密钥不会预填到编辑输入框；留空保留、输入新值替换，也可移除。地址改变 Origin 时需要重新绑定，复制连接不复制凭证。停用或删除默认所选配置后，发送会提示重新选择并保留草稿。

三个适配器分别实现 Chat Completions、Anthropic Messages 和 Gemini 原生 REST/SSE、图片与工具循环。DeepSeek 显式发送 thinking.type=disabled；其他协议遵循供应商默认，必要签名和原生工具关联随当前任务跨轮保留。思考强度控制尚未开放。HTTP 401/402/429 等展示宿主诊断，不显示原始错误正文。

浏览器调用需要供应商允许 CORS；Anthropic 浏览器直连使用其专用 Header。移动端不受浏览器 CORS 限制。基础地址允许 HTTPS 或本机 HTTP，局域网 HTTP 尚未开放。

云模式的相关项目资料会发送到配置的服务。工具只能读取当前项目，不能访问其他项目、.git、数据库或凭证。项目图片需通过 inspect_image，并且图片输入已开启，才会进入模型请求。

Android/iOS 使用 SecureStore 保存凭证；浏览器只在页面会话中保存，刷新需重新填写。开发者统一密钥不应分发给客户端。

启动任务会冻结连接、模型、参数及版本，密钥留在宿主租约；修改配置和打开配置页面不停止任务，不改变后续工具轮次。运行结束后回收被替换的旧凭证。历史记录使用启动时快照；旧任务无法确定的模型字段显示未知。

已用临时授权密钥连接 DeepSeek 官方服务，完成文字整理、连续修改、图片识别与文件保存、Git 恢复，以及 Android 重启后继续调用。验证使用合成资料，不代表所有模型或所有内容场景都已通过。

## 数据与版本

移动端：Expo 私有文件保存真实项目和 .git，SQLite 的 records 表保存项目、任务、transcript、设置和 operations；数据库 schema 版本 1。

浏览器：IndexedDB 数据库 agent-mobile-prototype，files store 保存真实 Git 仓库文件，records store 保存业务数据。与手机的数据不互通；清空站点数据会删除项目。

Git 后端使用 isomorphic-git 1.44.2 的标准仓库格式，经 Git CLI 读取验证。libgit2 桥接是后续原生实现；当前并未伪造版本 ID 或自建另一套快照历史。

每次修改保存 prepared 操作记录，应用文件，创建携带 operationId 的 Git 提交，再记录 committed/recorded。恢复时检查前后内容及提交标记，防止重复提交；无法对应的项目进入写入禁用状态，保留恢复数据。

“撤销修改”只允许撤销没有后续修改的任务；较早任务通过版本恢复。恢复产生新提交，已有历史和任务记录保留。图片差异展示修改前后预览，文本展示逐行新增/删除（每侧最多 12,000 字符）。

## 界面与编辑

- 外观在设置中选择“跟随系统 / 浅色 / 深色”，实时生效并保留。
- 手机会话输入区固定，键盘弹出时收起底部导航；桌面有项目侧栏和独立文件编辑侧栏。
- 原生新建/设置面板和全屏编辑器避让软键盘，输入时仍可操作确认与保存。
- 文字文件可在“阅读 / 编辑”之间切换，Markdown 阅读支持常见文本结构与项目内图片。
- 文件关闭、切项目、新建项目时保护未保存内容，支持“保存后离开 / 放弃修改 / 继续编辑”。
- 文件搜索、类型筛选、文件夹导航、图片缩略图、重命名和导出都有实际操作。
- 浏览器 Enter 发送任务，Shift+Enter 换行；编辑器 Ctrl/Cmd+S 保存。
- 会话按时间展示目标和回复，执行过程默认折叠，文件变化单独预览。
- 回复展示当前生成轮次的文字，最终只保留最终答案；中间轮次保存在 transcript，避免步骤说明与结果直接拼接。
- 同对话、同模式会携带最近 6 次目标与回复作为上下文；其他对话和旧工具调用不会重放。
- 每个对话的草稿和附件引用独立持久化；切项目/切对话/进入配置均保留。未保存文件或未完成写入的草稿会触发浏览器离开提示。

## 中断语义

- 任务执行期间同一项目禁止其他写入，工具按顺序执行。
- 提供文件列举、文本读取/搜索/写入、移动、删除和授权图片读取工具。
- 停止任务会取消网络及新的工具操作，已完成的文件修改保留。
- 重启先恢复未完成的文件/Git/数据库操作。
- 原先 running 的任务变成 interrupted，用户查看结果后可以发起新任务。
- 当前不自动续跑 Pi transcript、不重放未知远程请求，也不承诺后台常驻。
- 两分钟墙钟上限会中止执行；已有 Git 修改保留。

## 当前限制

- 单文件导入 5 MB；文本 256 KB；模型图片输入 1 MB；图片最多 2400 万像素，导入时检查格式头和尺寸；超大图片需要外部缩小后导入。
- 只有 Markdown、文本和 JPEG/PNG/WebP；空目录不单独版本化。
- 图片裁剪、缩放、语义修图和生成尚未实现。
- 原型按文件读取全文并计算 blob 修订号，较大项目的性能需优化。
- 写锁是当前应用实例内的锁；浏览器预览暂不支持多页面同时操作同一项目。
- SQLite 是通用 JSON records 表，尚未规范化为正式 schema；FTS、token 精确预算和历史清理未实现。
- 已记录操作保留恢复数据，尚无日志压缩和容量管理；大量图片版本会占用存储。
- 磁盘内容既不匹配修改前也不匹配修改后的异常部分写入，会冻结该项目；尚未提供交互式修复工具。
- 导出为单文件；完整仓库包、项目包和备份尚未实现。
- 没有应用层全盘加密、远程 Git、多设备同步、IntelligentUI 或网页执行。
- 浏览器流程与 Android API 36.1 模拟器流程已验证；Android SecureStore 保存后强制停止再调用成功。arm64 真机、原生掉电持久化和 iOS 编译尚待验证。

后续优先级：Android/iOS 真机验证 → libgit2 替换及原生一致性 → 更多模型兼容和图片处理 → 更完善的任务恢复和容量管理。
