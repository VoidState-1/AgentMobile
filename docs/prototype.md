# 原型体验与实现说明

日期：2026-10-13。

## 快速体验

运行 npm run web，打开终端显示的地址；或运行 npm run build:web 后运行 npm run preview，打开 http://127.0.0.1:4180。

1. 新建项目，例如“旅行资料”。
2. 打开 documents/notes.md，输入资料并保存；或导入文本/图片。
3. 切到 Agent，输入任务并点击“开始任务”。
4. 默认演示经过 Pi 的 list_files → read_text → write_text 循环，生成 documents/summary.md。
5. 点击“查看变化”，检查新文件；“撤销修改”恢复任务开始前的文件内容。
6. 在“历史”查看各次真实 Git 提交，恢复旧内容时会生成新提交。
7. 关闭并重新打开页面，项目和资料仍在浏览器本地存储中。

演示模式的步骤和文本模板都是预设的；它验证执行链路，不提供语义理解。

## 配置真实模型

右上角“模型设置” → “真实模型”，填写：

- 基础地址：例如 https://your-provider.example/v1，应用在末尾追加 /chat/completions。
- 模型名称：供应商提供的确切模型 ID。
- API Key：用户自己的凭证。
- 图片输入：确认所选模型支持图片后开启。

要求服务支持 Chat Completions 格式、SSE 和 tools/tool_calls。不同兼容服务仍可能有差异。浏览器调用需要供应商允许 CORS；移动端不受浏览器 CORS 限制，但仍需 HTTPS。

云模式的相关项目资料会发送到配置的服务。工具只能读取当前项目，不能访问其他项目、.git、数据库或凭证。项目图片需通过 inspect_image，并且图片输入已开启，才会进入模型请求。

Android/iOS 使用 SecureStore 保存凭证；浏览器只在页面会话中保存，刷新需重新填写。开发者统一密钥不应分发给客户端。

本次仅用模拟的远程 SSE 服务验证请求/工具协议，没有使用真实付费供应商或真实用户凭证。接通供应商后的质量、费用和服务特性需要另行测试。

## 数据与版本

移动端：Expo 私有文件保存真实项目和 .git，SQLite 的 records 表保存项目、任务、transcript、设置和 operations；数据库 schema 版本 1。

浏览器：IndexedDB 数据库 agent-mobile-prototype，files store 保存真实 Git 仓库文件，records store 保存业务数据。与手机的数据不互通；清空站点数据会删除项目。

Git 后端使用 isomorphic-git 1.44.2 的标准仓库格式，经 Git CLI 读取验证。libgit2 桥接是后续原生实现；当前并未伪造版本 ID 或自建另一套快照历史。

每次修改保存 prepared 操作记录，应用文件，创建携带 operationId 的 Git 提交，再记录 committed/recorded。恢复时检查前后内容及提交标记，防止重复提交；无法对应的项目进入写入禁用状态，保留恢复数据。

“撤销修改”只允许撤销没有后续修改的任务；较早任务通过历史恢复。恢复产生新提交，已有历史和任务记录保留。图片差异展示修改前后预览，文本展示完整前后内容（界面每侧最多 12,000 字符），尚不是逐行 diff。

## 中断语义

- 任务执行期间同一项目禁止其他写入，工具按顺序执行。
- 提供文件列举、文本读取/搜索/写入、移动、删除和授权图片读取工具。
- 停止任务会取消网络及新的工具操作，已完成的文件修改保留。
- 重启先恢复未完成的文件/Git/数据库操作。
- 原先 running 的任务变成 interrupted，用户查看结果后可以发起新任务。
- 当前不自动续跑 Pi transcript、不重放未知远程请求，也不承诺后台常驻。
- 两分钟墙钟上限会中止执行；已有 Git 修改保留。

## 当前限制

- 单文件导入 5 MB；文本 256 KB；模型图片输入 1 MB；图片最多 2400 万像素，导入时检查格式头和尺寸；超大图片需要外部缩小后导入。
- 只有 Markdown、文本和 JPEG/PNG/WebP；空目录不单独版本化。
- 图片裁剪、缩放、语义修图和生成尚未实现。
- 原型按文件读取全文并计算 blob 修订号，较大项目的性能需优化。
- 写锁是当前应用实例内的锁；浏览器预览暂不支持多页面同时操作同一项目。
- SQLite 是通用 JSON records 表，尚未规范化为正式 schema；FTS、token 精确预算和历史清理未实现。
- 已记录操作保留恢复数据，尚无日志压缩和容量管理；大量图片版本会占用存储。
- 磁盘内容既不匹配修改前也不匹配修改后的异常部分写入，会冻结该项目；尚未提供交互式修复工具。
- 导出为单文件；完整仓库包、项目包和备份尚未实现。
- 没有应用层全盘加密、远程 Git、多设备同步、IntelligentUI 或网页执行。
- 浏览器流程与 Android API 36.1 模拟器流程已验证；arm64 真机、原生掉电持久化、SecureStore 写入和 iOS 编译尚待验证。

后续优先级：Android/iOS 真机验证 → libgit2 替换及原生一致性 → 真实模型与图片处理 → 更完善的任务恢复和容量管理。
