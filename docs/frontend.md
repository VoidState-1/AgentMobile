## 1. 路由与页面责任

Expo Router 的 `src/app` 只处理页面映射和布局，业务界面在 features。`_layout` 组装 GestureHandlerRootView、SafeAreaProvider、导航 ThemeProvider、StatusBar 和 Stack。

| 路由                                             | 业务范围                                  |
| ------------------------------------------------ | ----------------------------------------- |
| `/`                                              | 工作台：对话、文件、Git、设置四区及编辑器 |
| `/models`、`/models/connection`、`/models/model` | 供应商连接与模型配置                      |
| `/mcp`、`/mcp/server`                            | 远程服务器、发现与项目授权、未知回执      |
| `/skills`、`/skills/edit`                        | 技能管理、包/资源编辑和版本               |
| `/settings/agent`                                | 系统提示词与执行限制                      |

路由不创建独立工作区或独立 RunKernel，使用同一 bootstrap 服务。进入配置页不会终止活跃任务。UI 不引用 adapters、SQL、GitPort 或凭证存储，文件选择/导出也走 AppServices.io。

## 2. 工作台职责与视图接口

[useWorkbench](../src/features/workbench/use-workbench.ts) 负责装配查询、编辑会话与以下命令模块。界面暂态仍属于 React，不增加业务数据库或新的全局 store。

| 模块                                                                        | 责任                                                              |
| --------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| [useProjectNavigation](../src/features/workbench/use-project-navigation.ts) | 项目创建、会话切换/命名/归档/恢复、侧栏及切换前的草稿交接         |
| [useTaskActions](../src/features/workbench/use-task-actions.ts)             | 发送前保存、草稿修订提交、停止/子任务取消、提案预览与任务产物路径 |
| [useEditorActions](../src/features/workbench/editor-actions.ts)             | 打开、编辑、保存、导入、重命名、删除及编辑离开保护                |
| [useGitActions](../src/features/workbench/git-actions.ts)                   | 暂存、提交、差异、历史恢复及任务撤销                              |
| [useDialogActions](../src/features/workbench/use-dialog-actions.ts)         | 共用的配置跳转和确认/保存后离开流程                               |

各视图接收明确的接口：`shell` 用于顶栏和主导航，`navigation` 用于项目对话树，`settings` 用于设置入口，`sheets` 用于输入/选择/确认弹层；`conversation`、`editor`、`files`、`git`、`runs` 分别服务对应工作区。删除了反射枚举函数的 CommandBindings 和包揽侧栏、设置、弹层的 dialogs 门面，不为旧调用者保留别名。

[Conversation](../src/features/workbench/conversation.tsx) 组织时间线与建议；[Composer](../src/features/workbench/composer.tsx) 管理输入框高度、焦点、添加菜单和输入工具行；[Exchange](../src/features/workbench/exchange-item.tsx) 负责单条运行详情与产物。草稿继续由 useConversationDraft 持久化，发送仍等待对应修订，不因组件拆分改变存储策略。

工作台使用单层 48px 顶栏，底部为“对话 / 文件 / Git / 设置”四区，键盘弹出时收起底栏。宽度 >=1,100 时项目对话树常驻左侧；窄屏使用 [侧栏覆盖层](../src/features/workbench/project-drawer.tsx)，通过顶栏入口打开、关闭按钮/遮罩/系统返回关闭。当前没有注册侧栏滑动手势，也不覆盖系统边缘返回。文件编辑仍为手机全屏、宽屏侧栏。

[ProjectTree](../src/features/workbench/project-tree.tsx) 直接投影全部项目与其对话，通过缩进表达归属。对话点击切换、长按展开重命名/归档操作，归档模式直接在同一树内恢复。顶栏点击当前对话标题原位修改，项目和对话列表不再使用旧弹窗。侧栏展开时背景从可访问树隐藏；输入型确认仍使用 Sheet。

当前对话的卡片输入框外边距 8px、圆角 8px；添加入口展开资料/技能动作，模型选择与草稿保存状态留在同一工具行。文件列表使用真实目录树、搜索、类型过滤及 Git 标记；项目与对话的切换仍先 flush 草稿，跨项目受编辑 guard 保护。

固定输入区、键盘与短视口回归是手机端主要约束，Web 不能替代 Android/iOS 验收。

四个底栏入口不依赖项目选择，未创建或未选中项目也可往返切换。对话、文件与 Git 在没有项目时显示对应空状态，并提供新建或选择项目入口；项目依赖限制只作用于实际业务操作，不能禁用主导航。

配置页使用同一单层顶栏、固定底部保存区和最大 820px 的内容范围。连接、模型、MCP 和技能条目以紧凑行及分隔线呈现，表单分节不再嵌套圆角卡片。执行预算、模型输出/温度/推理预算、MCP 超时使用单列数值行：名称、输入和单位同排，数值列对齐，范围校验错误在实际保存时呈现，不在每项下面重复范围说明。长地址与正文使用全宽输入。

分节没有普通说明信息按钮，也不显示“如何调用”“使用范围”等常驻教程。系统提示词、预算和模型参数的恢复默认操作放在所属分组的省略号菜单；MCP 工具名点击展开输入定义，行末开关直接表达授权状态。费用、远端自动调用后果、冲突和结果未知等关键信息仍在相应位置显示。模型与技能选择、创建/改名、未保存确认、资源编辑和差异共用小圆角、约 12px 内边距的弹层；触控目标仍至少 44px。

### 2.1 全局组件契约

| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |

这些组件按对象语义复用，不把全部列表压成一个万能 schema。项目树保留嵌套与长按行为，Git 文件行保留独立暂存/丢弃操作，编辑器和项目侧栏保留各自的全屏/侧栏外壳。

MCP 的 [UnknownCalls](../src/features/mcp/unknown.tsx) 同时用于全局列表和单连接详情；后者传 serverId 限定查询范围。模型检测的 [CheckResult](../src/features/model-config/check-result.tsx) 用于模型详情；连接的目录检测结果通过非模态 Toast 报告。SkillPicker 只接收项目、输入和选择/关闭/管理回调，不再依赖工作台控制器。

组件入口位于 [selection](../src/shared/ui/selection.tsx)、[primitives](../src/shared/ui/primitives.tsx) 和 [git-status](../src/shared/ui/git-status.tsx)。底部四区属于主导航，继续使用图标与文字，不与页面内标签混用。

阅读态顶栏只有编辑入口；编辑态显示保存，未修改时可完成编辑。点击保存成功且该编辑身份仍有效、期间无新输入时返回阅读态；快捷保存和未保存保护仍经同一保存用例。删除了重复的阅读/编辑标签栏。

供应商页直接排列 14 个常用供应商模板（见 core/models/presets.ts），不再使用顶栏加号、添加连接按钮或供应商选择弹层。实心绿色圆点表示凭证可用或无需认证的已保存连接，灰色空心圆点表示未保存或缺少凭证；该指示不代表实时在线或检测通过。未配置的模板直接进入预填表单；单连接直接打开编辑；同供应商多连接在所属行下展开。默认将自定义连接追加到模板之后，随后可与模板一起长按拖拽排序，列表末尾固定提供右侧加号的“添加其他供应商”。搜索按供应商名称/标识、连接名称及地址筛选；模板列表在首次使用时已有内容，搜索始终可用。连接保存后才显示模型目录与添加入口。设置入口投影当前模型、启用 MCP 数量及技能状态，MCP 数量代表配置启用，不宣称实时连接成功。

连接编辑器按对象而非分节表单组织：顶栏只显示“添加连接/连接设置”，连接名称紧邻供应商图标，铅笔按钮进入行内编辑；名称下一行显示供应商、协议与认证摘要，右侧是直接可见的启用开关。服务地址与 API Key 各占一行，标签在左、值在右，聚焦时用底边线标示；API Key 行提供显示/隐藏与移除，移除后显示带撤销的警告。协议、认证方式、兼容特性与 Anthropic 版本收进默认折叠的“高级设置”。模型区以“模型 N”标题承载搜索、目录刷新与添加入口，刷新位于搜索和添加之间；检测结果用自动消失的非模态气泡报告发现数量，失败时显示错误气泡，不再占用常驻卡片。普通模型行不重复来源信息。复制、删除与恢复默认图标进入顶栏“更多操作”页内浮层菜单，菜单不遮罩、不抢占焦点；底部只保留“保存连接”。

模型编辑器复用同一对象式布局：供应商图标、模型显示名（铅笔行内编辑）和“连接 · 协议”摘要组成身份行，右侧为收藏星标与启用开关；请求 ID、三项能力、参数、检测和默认选择均为单行字段或行内分段控件，不再显示能力来源注记。仅在身份、能力/参数、检测、默认等块之间使用分隔线；检测压缩为“文本/工具/图片”三个按钮并只渲染已有结果；默认选择合并为全局/项目/会话三个按钮，当前范围用主色标识。清除项目/会话默认、恢复默认参数和删除模型进入顶栏“更多操作”浮层菜单。

供应商列表使用 DraggableFlatList（Gesture Handler + Reanimated），复用 ActionRow/DisclosureRow 的长按与可访问性上移/下移动作。拖拽只排序供应商节点；末尾添加入口固定，展开组在拖动前收起。拖拽开始捕获 revision，保存失败回到服务快照中的当前顺序并显示错误。执行模式控件已移除，输入区只显示模型选择入口。

[ProviderIcon](../src/features/model-config/provider-icon.tsx) 在供应商列表、连接编辑与模型选择器复用：有效的用户上传优先，其次按明确 presetId 或已知地址主机匹配本地品牌 SVG，无法识别时使用节点式默认图标。匹配只影响显示，不推断 API 协议或模型能力。品牌资源来源和 MIT 许可见 [资源说明](../src/features/model-config/assets/README.md)。图标不发起远程 favicon/CDN 请求。

供应商身份头中的图标打开图片选择；上传后预览，保存连接才持久化，离开仍受未保存保护。已有上传图标时在“更多操作”中提供恢复默认动作。仅接受 PNG/JPEG/WebP、最大 256 KB，服务校验图片头、尺寸、编码与体积；失败保留已有草稿图标。图标损坏时回退到品牌/默认图标，连接的显示名与编辑入口仍可用。

## 3. 状态归属

| 状态                                                                      | 归属                                               |
| ------------------------------------------------------------------------- | -------------------------------------------------- |
| 项目/会话、配置、文件、Git、任务、轨迹                                    | AppServices 的业务事实；hook 保存查询投影          |
| 目标草稿与附件                                                            | ConversationService 持久化；输入 hook 跟踪保存状态 |
| projectId/conversationId/tab/appearance/commitDrafts                      | Zustand 界面状态                                   |
| 项目选择/主题持久偏好                                                     | PreferencesService；Zustand 只是投影               |
| EditorDocument、drawerOpen、弹层、review、confirmation、busy/error/notice | React 内存                                         |
| 已访问工作台页签及页内筛选/折叠状态                                       | React 内存；未访问页签不预先挂载                   |
| Agent 活跃执行                                                            | RunKernel；页面不拥有执行生命周期                  |

commitDrafts 是按项目分开的界面说明草稿，当前没有写入 PreferencesService；对话目标草稿则是真正持久化的数据。不要因为两者都叫草稿而假设行为相同。

## 4. 数据查询与实时订阅

[useWorkbenchData](../src/features/workbench/use-workbench-data.ts) 负责初始化、项目 snapshot、Run 分页和订阅：

- workspace recorded 通知刷新当前项目文件/Git，合并连续通知，避免每个模型 token 都读整个文件树。
- models/conversations 的快照订阅更新当前配置/对话目录。
- agent 快照订阅更新活跃运行与公开错误，文件刷新不依赖完成状态。
- runs 变更按当前 project/conversation/root 范围刷新历史，子任务独立查询。

查询使用 refreshId/historyRequest/scope 和当前 UI 选择作晚到结果过滤。显示投影的 snapshotProjectId/taskScope 不属于当前选择时直接显示空/加载状态，不先用旧项目数据冒充新项目。

历史加载更多按 id/OID 去重，刷新首批后保留用户已展开旧页。切换项目或会话时重建查询 scope，旧 cursor 不带入新范围。

历史运行详情是可丢弃的 UI 读模型，按 runId 与摘要 revision 缓存并合并同键在途查询，最多保留 50 个条目；失败项从缓存移除，超限按最近访问顺序淘汰。缓存只保存 RunsApi 的公开 detail/trace/children 投影，不作为业务事实来源。实时运行退出内核活动列表后，对话行先保留最后公开 RunView，终态详情到达后再切换。

### 4.1 配置页共用机制

模型、MCP 与 Skills 各自保留领域入口 hook，组合 [useAppServices](../src/shared/use-app-services.ts)、[useServiceSnapshot](../src/shared/use-service-snapshot.ts) 与 [useAction](../src/shared/use-action.ts)。快照通过 useSyncExternalStore 订阅；未初始化时使用稳定的空配置。useAction 提供同步互斥、busy 和 publicError 格式化，配置、Agent 设置、工作台及远端核对共用同一命令生命周期。

[useProjectSelection](../src/shared/use-project-selection.ts) 共用项目加载、持久偏好与手工选择，服务 MCP 和 Skills 授权页面。删除了三个旧 common 文件与组件重导出；调用者直接引用实际所属模块。工作台初始化仍由 useWorkbenchData 负责格式校验与重建流程，不强行合并成普通配置订阅。

[useDraftGuard](../src/shared/use-draft-guard.tsx) 独立处理表单导航保护并复用 ConfirmSheet；与工作台共用 [useBeforeUnload](../src/shared/use-before-unload.ts) 的 Web 离开提示。运行状态文字由 shared/format 的 runStateLabels 统一投影到消息、活动任务和子任务，避免同状态使用不同名称。

## 5. 编辑会话身份与保存

[EditorDocument](../src/features/workbench/types.ts) 保存唯一字符串 identity、项目/路径/基础 revision、当前与已保存 text/name、文件类型、换行约定、editState 和草稿修订。editState 保存区域、模式和选区，正文只有 text/savedText 两个职责明确的版本。每次重开或外部干净刷新都会生成新 identity，旧通信和回执不能覆盖新会话。

[useEditorSession](../src/features/workbench/use-editor-session.ts) 提供唯一 setEditor，同步更新 ref/state，并串行通过 AppServices 保存元数据草稿。关闭、导航、全局保存和切后台先向浏览器内核请求 flush，再等待草稿落库。新建草稿使用项目内的 .new-document 元数据键，不创建同名工作区文件。

[DocumentHost](../src/features/document/document-host.tsx) 校验带会话 channel 的消息和完整源码投影，Web 使用仅 allow-scripts 的 iframe；手机使用禁止文件访问、外部导航和网络资源的离线 WebView。浏览器只能提交当前文档候选内容、请求项目图片及显式点击的链接，不能指定保存的项目或路径，不能访问 AppServices、数据库、凭证或任意原生能力。主题由宿主传入，不保留独立原型的本地存储、示例数据、导入服务或全局主题状态。

右滑保存或顶栏保存经过宿主实际 writeText 成功后才关闭相应区域。只保存目标及其关联区域，其他草稿继续保留。保存与全局宿主操作期间暂停源码输入，避免回执覆盖；文件名输入也在保存期间暂停。源码输入撤销仍使用 CodeMirror，文件历史仍由 Git 管理。切换分块/全文模式时若有未保存内容，复用宿主确认弹层明确保存、放弃或继续编辑，不自动写入；未保存时禁止导出旧文件版本。

写文件前，草稿持久化 pendingSave、saveOperationId 和 savePath。workspace.writeText 使用稳定 operationId 重试已记录的工作区事务；读回实际内容与候选字节一致后才更新 revision 和剩余区域；换行字节发生外部变化也保留旧基础版本并报告冲突。若结果未知，保留保存意图并暂停编辑，提供重试保存；读取到已落盘的目标内容则确认成功，不再次覆盖。草稿元数据与文件/Git 依然没有跨存储事务。

## 6. 外部变化与未保存保护

工作区通知到达后，打开文件 revision 改变：无本地脏内容则用 preview 更新；有本地修改则保留并置 externalChanged；外部删除且无脏修改则关闭。读取前后的编辑 identity/revision 都匹配才应用结果。

dirty 为 fresh 或 text/name 与 savedText/savedName 不一致。切项目、关闭编辑器等受 guard 保护，用户可保存后继续或放弃；确认结构中的 afterPerform 保存原导航动作，不能确认后忘记执行原选择。

Web 在编辑或目标草稿尚未保存时设置 beforeunload 提示。文件草稿通过业务库保存，重开相同文件恢复区域和选区；文件与已记录保存意图一致时对齐新基线并保留其他区域，外部内容不匹配则保留旧基线和冲突提示。用户可显式放弃草稿后重新载入。强杀前尚未送达宿主或尚未落库的最后输入不具备持久性保证。

## 7. 运行与轨迹视图

会话时间线按目标、执行步骤、最终结果组织，text/reasoning/tool 轨迹内联展示。历史先查询摘要，初始三条渲染项预取详情，避免路由切换期间可见性回调尚未触发而一直显示加载；其余项进入可见区后读取详情。节点和长正文仍分页读取，子任务通过 childRunIds 关联步骤，writer 提案可查看独立差异。

最终 response 单独来自 RunDetail，不依赖前 50 个节点已全部载入。推理标签使用 visibility，不通过模型名称推断开源/闭源身份；unavailable 显示不可用状态。

[trace-groups](../src/features/workbench/trace-groups.ts) 将 edit_text 与 write_text/delete_file/move_file 一起归入“修改”，不误标为远程 MCP；工具详情使用有界替换摘要和原有错误/回执展示。它只合并相邻 tool 节点。正文和公开推理始终构成分组边界，不能为折叠工具而挪动顺序。读取、搜索、图片、修改、Git、Skills、MCP、子 Agent 使用各自图标；单调用直接显示详情，多调用以次数摘要默认折叠，展开内容最高 280px 并可独立滚动。调用数变化时稳定的 ScrollView 与 ToolStep 宿主不卸载，保留现有工具行状态。含子任务或异常回执的组默认展开，收起后仍显示异常摘要。分页追加沿用首个节点 ID，保留展开状态；原始轨迹与持久化结构不变。

产物使用紧凑文件行：文件名打开当前项目文件，变化图标查看该任务的历史差异。已移动/删除的文件不能直接打开，历史差异仍可查看。

当前实现仍有活跃运行的内存 trace 和内部完整读取路径，UI 分页不能代替整个内核的长任务内存审计。

## 8. 原始文件、通用文本、Markdown 与图片

普通导入不使用文件扩展名/MIME 白名单，调用 write 保存原始字节（当前单文件操作预算 20 MiB）。按内容识别的文本导入 documents/，其余导入 assets/。文件列表可筛选全部/文字/图片/其他，二进制和其他编码不会被当作文本解码。新建/重命名保留合法名称与相对路径校验，改后缀只改名称，不转换字节。

预览使用 kind/mimeType/size/unavailableReason。无法展示的文件显示大小与原因，提供导出、重命名和删除，不提供文本编辑按钮；大文本也可保存而不进入全文编辑。文本编辑器通过 writeText 保存完整输入，执行 1 MiB、严格 UTF-8、无 NUL 及已有内容类型检查。图片按实际内容识别，改为其他后缀仍按原图展示；任务附件也使用内容类型，而非路径后缀判断。

阅读模式仅对 `.md`、`.markdown` 使用 Markdown 排版；其他文本用可选择、等宽的原文预览，保留空白和 Markdown 标记，HTML/SVG/脚本均不执行。所有文本使用同一 CodeMirror 内核；非 Markdown 文本提供原文/编辑模式，Markdown 提供分块/全文模式。文本内部统一 LF，写回时还原文件原有的 CRLF/CR/LF 约定；二进制和图片不进入源码编辑器。保存、并发保护、导出与 Git 继续通过 AppServices。

差异视图遇到二进制、超预算或两侧类型变化时展示前后字节数与原因，不显示乱码或虚构行数；可预览文本/图片仍展示内容差异。

[文档内核](../src/features/document/browser/editor.js) 使用单个 CodeMirror 文档保存原始 Markdown，Markdown-it 渲染关闭范围，支持 CommonMark、表格、删除线、任务列表与嵌套结构。旧自制解析器和原文 TextInput 已移除。对话正文/公开推理通过共享 [render](../src/features/document/render.ts) 和 MarkdownReader 渲染；Web DOM 与原生只读 WebView 均递归 patch 兼容节点，只更新变化区段并尽量保留未变节点。Markdown 结构变化时重建不兼容节点，图片 revision 变化仍强制重载资源。

阅读块左滑进入；编辑块右滑保存、左滑放弃。允许多个区域同时开放。相邻区域之间光标、选区、退格连续；跨块修改建立关联并一起保存/放弃。灰底横向铺满，零外边距、零圆角，文字对齐正文，上下保留 8px 内边距。没有块内标签、画笔或保存/取消图标。

保存权限范围与可见源码范围分开：连接换行只在相邻区域同时开放时暴露；关闭中间块后隐藏继承的连接换行，原文不变。最终派发入口检查所有写入并限制光标端点，包括关闭常规过滤器的历史事务。边界光标朝向源码，atomicRanges 只包含只读替换组件；分隔符、文档首尾和预览区域不成为编辑落点。手势按实际 DOM 行/片段归属，不回退到旧选区；共享一行时只移动目标文字。切换阅读与编辑后以块的屏幕位置锚定滚动。

HTML 渲染关闭，不执行脚本。图片从 Markdown 文件目录解析，经 safePath 和 AppServices.preview 读取，拒绝 scheme、绝对路径、反斜杠、控制字符和越界；只接受 PNG/JPEG/WebP 的 data URI。图片版本变化会失效缓存并重新读取，旧请求不覆盖新内容。外部图片不自动联网，外部链接只在用户点击后交给宿主验证 HTTP/HTTPS 并打开。

## 9. 主题与交互约定

[theme](../src/shared/theme.ts) 提供语义颜色、typography（正文、标签、辅助信息、元数据、标题）与 workbenchMetrics（顶栏、热区、边距、正文和圆角）；appearance 为 system/light/dark，持久化选择并同步导航与状态栏。业务组件取 theme token，避免只适配浅色的硬编码背景和文字。

shared/ui 提供基础文本、按钮、输入和复合交互；业务文字通过 T 的 variant 选择排版角色。ESLint 禁止页面直接导入原生 Text/TextInput/Modal；TextInput 类型导入可用，只有共享弹层、全屏编辑器和项目侧栏可拥有 Modal 外壳。工作台页签按首次访问惰性挂载，挂载后保留实例和页内状态；非活动页立即禁用触摸并移出无障碍树。主页签淡入，弹层与窄屏侧栏使用系统过渡，useReducedMotion 启用时即时切换。保持紧凑、清晰的工具风格，关键按钮可访问名称应稳定，便于屏幕阅读器与 Playwright/ADB 定位。模型 Key 等秘密字段不以普通结果文字展示。

当前文件树、项目/对话侧栏和 Git 历史仍以 ScrollView 渲染已加载条目，没有大数据集虚拟化；页面保留只减少往返切换时的重新挂载，不限制首次读取和长列表的渲染成本。图片缩略图仅随已保留的列表实例存活，尚无跨实例字节预算缓存。

设计验收遵循五条规则：屏幕空间承载有效信息；界面元素表达相关的对象、状态与操作；结构本身说明关系；操作依附对象，低频动作进入上下文菜单；文案只补充布局与反馈无法表达的信息。不以机械并列输入框、缩小字体、每项附注或增加信息图标代替信息结构设计。

useAction 的 pending ref 防止同一个界面 action 重复执行；这只是交互约束，服务 revision、锁和幂等不能因此省略。短 notice 到期清除，错误保留到明确动作/状态处理。

## 10. 前端扩展流程与验证

新增交互先查上面的复用表并检查现有调用者，确认不能组合已有组件后再增加新抽象。UI 入口约束由 [测试](../tests/ui-boundaries.test.ts) 验证。新增交互先判断是业务事实还是 UI 瞬时状态；业务能力先增加 AppServices 及用例，UI 再提供操作。新页面复用 shared 主题与服务入口，不接入底层 adapter。

影响保存/切换/订阅需覆盖：保存期间输入保护、同路径重开、旧查询迟到、跨项目通知、草稿切换、深浅主题、360px/短视口、键盘与未保存保护。避免只测试渲染了某个按钮。
